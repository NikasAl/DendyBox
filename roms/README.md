# ROM

Папка для ROM-файлов, из которых собираются приложения DendyBox.
**Один ROM — одно приложение** («одна игра — один картридж»): в APK зашивается
ровно один ROM, переключения между играми внутри приложения нет.

Есть и второй формат — **сборник «X игр в 1»**: одно приложение с меню выбора
нескольких зашитых игр (см. раздел «Сборники» ниже).

## Как добавить игру

1. Положите ROM (iNES `.nes`, также поддерживаются `.unf`/`.fds`) в эту папку.
   Проверить формат: `./scripts/check_rom.sh roms/имя_файла.nes`
2. Желательно описать его в `games.json` (лежит здесь же, коммитится в git):

```json
{
  "robocop3.nes": {
    "flavor": "robocop3",
    "title": "RoboCop 3",
    "versionName": "1.1",
    "versionCode": 2
  }
}
```

   * `flavor` — имя варианта сборки и хвост package id:
     `com.dendybox.app.<flavor>` (строчные латиница/цифры, сегмент не может
     начинаться с цифры; не может начинаться с «test» — ограничение AGP).
     Если не указать — берётся имя файла без расширения.
   * `title` — название игры в лаунчере: «DendyBox: <title>».
   * `versionName`, `versionCode` — версия ЭТОГО приложения (см. ниже).
     Не указаны — по умолчанию 1.0 / 1.

   Если `games.json` не трогать, flavor создастся сам из имени файла
   (`RoboCop 3 (E).nes` → flavor `robocop3e`).

3. Соберите: `./scripts/build_release.sh robocop3` (см. README.md).

## Сборники («X игр в 1»)

Вместо одного ROM можно зашить в приложение сразу НЕСКОЛЬКО игр любых
мапперов — при запуске приложение покажет меню выбора поверх постера
сборника (в духе пиратских мультикартов Денди), а «Выход из игры» в меню
паузы вернёт в это меню.

Для этого опишите сборник в `games.json`: запись с массивом `games` вместо
файла-ключа. Файл с именем ключа (здесь `kontra8in1.nes`) не нужен — ключ
служит только идентификатором записи:

```json
{
  "kontra8in1.nes": {
    "flavor": "kontra8in1",
    "title": "Контра: Сборник",
    "menuAlign": "left",
    "games": [
      { "file": "25_Contra.nes",       "title": "Контра" },
      { "file": "24_Super_Contra.nes", "title": "Супер Контра" },
      { "file": "203_TaleSpin.nes",    "title": "Чудеса на виражах" }
    ]
  }
}
```

Правила:

* `file` — имя ROM-файла из этой папки (`roms/…`), расширения `.nes`/`.unf`/
  `.unif`/`.fds`; `title` — название в меню (не задано — имя файла без
  расширения). Минимум 2 игры, максимум ограничен только разумным размером
  APK (каждый ROM зашивается целиком).
* **Любые мапперы** — MMC1, MMC3, MMC5, UNROM и т.д.: ядро FCEUmm определяет
  маппер само, никаких патчей игр не требуется (в отличие от ROM-мультикартов).
* Сборка: `./scripts/build_release.sh kontra8in1` — как у обычной игры.
* Версия сборника задаётся так же (`versionName`/`versionCode` записи) и
  обновляется через `./scripts/bump_version.sh kontra8in1 1.1`.
* Иконка лаунчера — `metadata/<flavor>/icon.png`, как у обычной игры.
* **Фон меню (постер)** — `metadata/<flavor>/background.png` (или `.jpg`,
  `.webp`): картинка на весь экран за списком игр. Файл опционален: нет —
  меню на чёрном фоне. Перед упаковкой в APK сборка автоматически пережимает
  постер в WebP (длинная сторона ≤ 2048px; тяжёлый PNG на 2–3 МБ превращается
  в 200–400 КиБ; файлы меньше 256 КиБ вставляются без перекодирования),
  оригинал в `metadata/` остаётся нетронутым. Рекомендации: **горизонтальный**
  формат — приложение работает в альбомной ориентации (например 1920×1080
  или шире, длинная сторона до ~3000px); под список игр оставляйте полосу
  по центру экрана (или сместите композицию к краю и задайте `menuAlign`);
  сверху и снизу приложение само добавляет мягкое затемнение, чтобы шапка
  и подсказки читались.
* **Выравнивание меню** — `"menuAlign": "left"` (или `center`/`right`, по
  умолчанию `center`): как прижаты шапка, плашки игр и подсказка/выход.
  Удобно, когда композиция постера смещена к краю: например для постера с
  картинкой справа задайте `left` — весь текст встанет слева.
* Конфиг игры (`roms/<flavor>.json`: netplay/damage) применяется ко ВСЕЙ
  сборке: повреждение байта урона имеет смысл только если игры похожи.
  Исключение — пресеты комбо-кнопок: у каждой игры сборника они свои
  (раздел `combos` в записи игры, см. ниже).
* Свои комбо-кнопки (созданные в «Комбо-кнопках») тоже привязаны к игре:
  набор, созданный при активной игре сборника, показывается и играется
  только в ней и переживает перезапуск; в других играх сборника его нет.
  Для одиночной игры свои кнопки общие, как раньше. Пресеты и свои кнопки
  отключаются тумблером «На экране» независимо друг от друга. В настройках
  управления комбо-кнопки можно разделить на несколько групп (у каждой —
  своё место, размер и название) и перетаскивать кнопки между группами;
  расстановка групп сохраняется при переключении игр сборника.
* Сейвы, чит-коды и сетевая игра работают с каждой игрой сборника отдельно:
  всё привязано к контрольной сумме конкретного ROM, состояние одной игры не
  влияет на другую. Автосейв при выходе в меню сборника тоже сохраняется.
* Если одна из игр сборника битая, при её запуске появится сообщение об
  ошибке с кнопкой «В меню сборника» — остальные игры продолжают работать.

Как это устроено внутри: сборка кладёт все ROM в APK (`assets/games/0.nes`,
`1.nes`, …) и манифест `assets/games/games.json` (вместе с фоном
`background.*`, если он есть); приложение при старте видит манифест и
показывает меню (`ui/screens/CollectionMenu.kt`), а выбранный ROM загружает
в ядро как обычную игру.


## Версия игры (versionName / versionCode)

Версия задаётся по flavor'ам в `games.json` и при сборке пробрасывается в
манифест APK (имя файла тоже собирается с ней: `DendyBox-robocop3-1.1-release.apk`).

* Новая игра стартует с **1.0** (`versionCode` 1) — поля можно не указывать.
* Чтобы выпустить обновление игры в магазине (RuStore и др.), увеличьте ей
  `versionName` и обязательно `versionCode` — он должен строго расти;
  версии других игр при этом не трогаются, каждая собирается со своей.
* Удобный способ:

```bash
./scripts/bump_version.sh robocop3 1.2      # версия 1.2, versionCode +1 (авто)
./scripts/bump_version.sh robocop3 1.2 7    # versionCode задан явно
./scripts/bump_version.sh robocop3          # посмотреть текущую версию
```

* Резолв версий печатается при каждой сборке:
  `DendyBox: версии — robocop3 1.1 (2), soccer 1.0 (1), …` — проверьте строку
  перед выпуском обновления.
* Версия приложения передаётся в рукопожатии сетевой игры (обмен
  HELLO/OK между телефонами), так что на обеих сторонах удобно сверять,
  одинаковые ли APK установлены.

## Важно

* **ROM'ы не коммитятся в git** (репозиторий публичный): `.gitignore` игнорирует
  всё содержимое папки, кроме этого README и `games.json`. Файлы остаются
  только на вашем диске — не потеряйте их.
* Приложение при запуске копирует ROM во внутреннее хранилище и загружает в ядро.

## Конфиг игры (опционально, roms/<flavor>.json)

При сборке файл `roms/<flavor>.json` попадает в APK как `game.json`
и задаёт опции конкретной игры. Файл полностью необязателен.

Пример:

```json
{
  "netplay": true,
  "damage": {
    "addr": "0x00F0",
    "mode": "dec",
    "value": 0
  }
}
```

### Видимость сетевого режима (`netplay`)

* `true` (по умолчанию, если флага нет) — в меню паузы есть пункт
  «Игра по сети (2 игрока)».
* `false` — игра одиночная: пункт меню сети скрывается целиком
  (пример: `robocop3.json`).

### Вибрация при получении урона (`damage`)

Если у игры есть байт памяти, который меняется при получении урона
(HP, шкала здоровья, байты-метки попадания — адрес ищется в fceux через
Hex/Memory viewer), можно включить вибрацию телефона при уроне.

Создайте файл `roms/<flavor>.json` рядом с ROM (для flavor robocop3 —
`roms/robocop3.json`); при сборке он попадёт в APK как `game.json`:

```json
{
  "damage": {
    "addr": "0x00F0",
    "mode": "dec",
    "value": 0
  }
}
```

Поля:

* `addr` — адрес наблюдаемого байта: число или hex-строка (`"0x00F0"`,
  `"$00F0"`). Поддержана базовая RAM `$0000–$07FF` (fceux показывает её
  в RAM viewer); зеркала `$0800–$1FFF` тоже работают — адрес сводится к
  базовой RAM. Адреса WRAM `$6000+` не поддержаны.
* `mode` — когда считать, что был урон:
  * `dec` — байт уменьшился (типичный случай: HP падает от удара);
  * `inc` — байт увеличился (шкала «повреждений», растущая от удара);
  * `eq` — байт стал равен `value` (байты-метки: игра записывает
    конкретное значение в момент попадания);
  * `change` — любое изменение байта.
* `value` — эталон для `mode: "eq"` (число или hex-строка).

Как найти адрес: в fceux откройте Hex editor, найдите байт HP/здоровья
(искать известное текущее значение здоровья), ударьте персонажа и
посмотрите, какой байт изменился ожидаемым образом. Проверьте пару раз —
байтов, меняющихся при любом событии, в игре много.

Поведение в приложении:

* раздел `damage` есть → в настройках появляется переключатель
  «Вибрация при получении урона» (короткий импульс, не чаще раза
  в 250 мс — непрерывный слив HP не «тараторит»);
* раздела нет → настройка вибрации в интерфейсе не показывается вовсе:
  другой вибрации (по нажатиям кнопок) в приложении нет.

Накладные расходы на производительность: одно сравнение байта RAM за
кадр внутри нативного цикла (наносекунды); при выключенной настройке
проверка не выполняется вовсе. Пример конфига: `damage-watch.example.json`.

### Пресеты комбо-кнопок (`combos`)

Раздел задаёт программируемые комбо-кнопки, характерные для игры
(суперудары, спецприёмы): они появляются на игровой поверхности
автоматически, отдельным блоком внизу по центру (позиция блока и масштаб
меняются в редакторе управления, блок «Комбо-кнопки»). Пресеты нельзя
редактировать в приложении — их задаёт картридж; свои кнопки добавляются
в меню паузы → «Комбо-кнопки».

Где задаются пресеты — по одному на каждый ROM:

* **одиночная игра** — раздел `combos` в `roms/<flavor>.json`;
* **сборник** — раздел `combos` в записи игры в `roms/games.json`
  (переносится сборкой в манифест сборника): у каждой игры сборника —
  свой набор, при переключении игры набор комбо-кнопок меняется;
* у записи игры сборника без раздела `combos` показываются общие пресеты
  конфига сборки (`roms/<flavor>.json`); явный пустой `"combos": []`
  отключает пресеты у этой игры.

```json
{
  "combos": [
    { "name": "Суперудар", "steps": [ { "b": "A", "d": 0, "w": ["B"] } ] },
    { "name": "Ультра", "steps": [
      { "b": "DOWN", "d": 0, "h": 100 },
      { "b": "DOWN", "w": ["RIGHT"], "d": 50, "h": 100, "anchor": "press" },
      { "b": "RIGHT", "d": 50, "h": 100, "anchor": "press" },
      { "b": "B", "d": 0, "h": 150 }
    ] }
  ]
}
```

Поля:

* `name` — подпись на кнопке (короткое, 1–2 строки);
* `steps` — последовательность шагов. Каждый шаг:
  * `b` — кнопка (`LEFT`/`RIGHT`/`UP`/`DOWN`/`A`/`B`/`START`/`SELECT`);
  * `d` — пауза в мс перед началом шага (кратно 50, 0–500): отсчитывается
    от ОТПУСКАНИЯ предыдущего шага, а при `anchor: "press"` — от его
    НАЖАТИЯ (перекрывающиеся удержания); у первого шага — от нажатия
    комбо-кнопки; пауза необязательна (нет — 0);
  * `w` — массив дополнительных кнопок: нажимаются одновременно с `b`
    и отпускаются вместе с ней (например `"w": ["B"]` при `b: "A"` —
    A+B разом);
  * `h` — длительность удержания набора в мс (кратно 50, 50–500;
    нет — 100): press-and-hold вместо клика.

Границы строгие: значение паузы/удержания вне границ или мимо сетки 50 мс
делает запись битой (сборка проверяет структуру пресетов и падает
с понятной ошибкой, шаги с неизвестными кнопками тоже).

Живой пример — `roms/games.json`: у сборника «Черепашки Ниндзя» у каждой
игры свои приёмы («Прыжок-удар» из TMNT; «Суперудар» и «Прыжок-удар»
из TMNT II; «Суперудар», «Прыжок-удар» и «Бросок» из TMNT III; десять
пресетов из Tournament Fighters — см. ниже), у сборника «Контра» —
«Автоогонь» (удержание B) для каждой из трёх игр.

#### Пресеты TMNT II и TMNT III (NES) — по справочникам

Пресеты «Черепашки Ниндзя II» и «… III» собраны по независимым
источникам (вводы сходятся):

1. Официальный мануал TMNT II (Ultra Software, 1990; OCR-скан
   archive.org, «Teenage Mutant Ninja Turtles II — The Arcade Game
   [NES-2N-USA]», раздел «Controlling Your Turtle»): **A = прыжок,
   B = атака**; «To jump and attack at the same time, carefully press
   the A Button and B Button simultaneously»; прыжок-удар — «press the
   A Button, then the B Button while pressing the Control Pad Left or
   Right»; энергия тратится только «each time you're wounded by an
   enemy»; разбегов/рывков в мануале нет.
2. GameFAQs, FAQ 7055 по TMNT II (процитирован в поисковой выдаче
   GameFAQs — полная страница закрыта антиботом): «If you can do the
   Special Attack (**A and B
   together**), you will have no problems beating this game», спец
   «destroys all Foot Soldiers in a single hit» и «should be used in
   all situations» (платы здоровья нет); всего три атаки (обычная,
   прыжок-удар, спец) — рывков нет; прыжок-удар несёт черепаху через
   экран (идёт с зажатым направлением).
3. Wikipedia, «TMNT III: The Manhattan Project» (геймплей): спецприём —
   «pressing B and A simultaneously… a portion of their energy will be
   lost, unless they are on their last bar of life»; тосс-атака —
   «holding the D-pad downwards while pressing B»; управление
   «mostly unchanged from the second NES game».
4. StrategyWiki, «TMNT III / Gameplay» (Combat): Special Attack — обе
   кнопки строго одновременно, снимает 1 полосу из 16 (на последней
   полосе — бесплатно); Throw «throws enemies back», некоторым врагам
   не работает, урон больше обычной атаки; в воздухе — diving jump
   kick.
5. ConsoleDatabase (cheats/nes/teenagemutantninjaturtles3) + GameFAQs
   FAQ 3110 + SPOnG «Replay» (2010): спецприём TMNT III называется
   «Tubular Turbo Attack» (A+B одновременно); по черепахам: Лео —
   Cyclone Sword Spin, Дон — Knockout Roll, Майки — Kangaroo Kick,
   Раф — Power Drill Attack.

Пресеты (для движения ВПРАВО; влево — отредактируйте шаги RIGHT→LEFT
в своей кнопке):

| Кнопка | Приём | Ввод по источникам | Пресет |
|---|---|---|---|
| TMNT II «Суперудар» | Special Attack (все черепахи) | A+B одновременно | A+B в один кадр (`w`) |
| TMNT II «Прыжок-удар» | Jump Kick | A, затем B при зажатом ←/→ (мануал) | RIGHT 400 мс, A в него же, B на 150-м мс |
| TMNT III «Суперудар» | Tubular Turbo Attack (−1/16 полосы) | A+B одновременно | A+B в один кадр (`w`) |
| TMNT III «Прыжок-удар» | Diving Jump Kick | A, затем B в воздухе (с ←/→) | как у TMNT II |
| TMNT III «Бросок» | Toss/Throw | зажать ↓, нажать B | DOWN 250 мс, B внутри |

Отмеченные допущения (источник требует иное — приведено к ближайшему
валидному):

* **Тайминги в источниках не публикуются** (фреймдаты NES-версий нет) —
  ритмы реконструированы под сетку 50 мс: 150 мс от прыжка до удара
  ≈ 9 кадров NES (черепаха уже в воздухе), RIGHT держится 400 мс —
  накрывает весь прыжок с ударом (по FAQ 7055 прыжок-удар «несёт через
  экран»), DOWN в броске — 250 мс с B внутри удержания.
* **«Одновременно» = один кадр**: шаг с `w` зажимает A и B в один и тот
  же мс. Разнесённые тапы здесь опасны: по мануалу TMNT II «A, затем B»
  — это уже прыжок-удар, а не спецприём (в Tournament Fighters,
  наоборот, «A чуть раньше B» давало спец с доп. прыжком — тут границы
  строже).
* **Рывков в обеих играх НЕТ** — прежний пресет «Рывок-удар» (→→B)
  удалён как несуществующий приём: по FAQ 7055 у черепах только три
  атаки, Wikipedia подтверждает «mostly unchanged» в TMNT III. Ключ
  отключения «Рывок-удар» становится дремлющим — это штатно.
* **Спецприём TMNT II бесплатен** (в отличие от аркады и TMNT III):
  мануал списывает трату энергии только на ранения, FAQ 7055 советует
  спец «in all situations». В TMNT III спец снимает 1/16 полосы жизни
  (на последней полосе — бесплатно, StrategyWiki/Wikipedia).
* **«Бросок» требует врага рядом**: без врага в зоне ввод просто ничего
  не делает; некоторым врагам не работает вовсе, зато по StrategyWiki
  урон больше обычной атаки. Броски TMNT II (схватить вплотную, затем
  B) — позиционно-зависимы, в пресеты не включены.

#### Пресеты «Tournament Fighters» (NES) — по справочникам

Пресеты «Черепашки Ниндзя Турнир» собраны по трём независимым источникам:

1. Официальный мануал NES (world-of-nintendo.com, «NES Instruction
   Manuals: Teenage Mutant Ninja Turtles Tournament Fighters»):
   управление **B = Punch (кулак), A = Kick (пинок)**; «accumulate» для
   зарядовых приёмов — «держать около 2 секунд»; бросок шара — «hold D,
   then LR+R+B» (↓,↘,→+B); спецприёмы по персонажам.
2. GameFAQs, FAQ 3111 «Move List» (E. Paiva aka E-Nice, 28.02.1998):
   Ultra Attack = Down,Toward+B **только когда персонаж держит красный
   шар** Сплинтера (схватить: встать над шаром и нажать ↓+B); у черепах
   →→+A «Flying Kick» и →→+B «Flying Elbow Smash»; вводы спецприёмов
   всех семи бойцов.
3. IGN, «Moves List/FAQ» (the-micro-man, 2007): подтверждает Ground
   Flame Шреддера (→,↘,↓,↙,←+B) и «Gauntlet Blur» (B×3+).

Отмеченные допущения (источник требует иное — приведено к ближайшему
валидному):

* **Тайминги в источниках не публикуются** (фреймдаты NES-версии нет) —
  ритмы (перекаты направлений с перекрытием 50 мс, двойной тап с
  интервалом 100 мс) реконструированы под сетку 50 мс: каждое направление
  держится 100 мс, следующее стартует через 50 мс после НАЖАТИЯ
  предыдущего (`anchor: "press"`), кнопка атаки — при отпускании
  последнего направления или внутри него, как указано в таблице.
* **Зарядовые приёмы**: источник требует «держать ~2 секунды», а
  удержание шага ограничено 500 мс — заряд собран из 4 цепных шагов по
  500 мс: стык отпускание/нажатие попадает в один и тот же мс, эмулятор
  читает биты по кадрам и видит непрерывное удержание (заряд не сбрасывается).
* **«Ультра» требует шар**: сначала взять шар (встать над ним и нажать
  ↓+B — мануал указывает просто B), затем нажать кнопку «Ультра»;
  без шара движение ничего не делает.
* Не включены: «Gauntlet Blur» Шреддера (частое постукивание B —
  тривиально вручную; шаги-«тапы» через сетку 50 мс дают 10 тапов/с,
  при желании собирается своим комбо), низкая Kangaroo Майки
  (→+A — заменить кнопку B на A в «Зарядке B»), подсечка Лео (↓+A) и
  броски (зависят от позиции — вплотную к сопернику).
